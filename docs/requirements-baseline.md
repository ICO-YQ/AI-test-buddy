## 0. 路由结论：场景命中与必带清单

| 命中信号 | 命中场景 | 必带清单 |
|---|---|---|
| 任务分派、成员、SLA、看板 | 企业服务 | 工单 SLA + 服务度量口径 |
| 权限、角色、数据隔离、审计 | B 端管理系统 | 权限矩阵 + 存量迁移 |
| Skills Hub、远程仓库、API、MCP、计量 | 开放平台 / SaaS | API 8 项 + 配额规则 + 指标口径 + **资金三件套（计量计费属资金场景）** |
| Confluence/Notion 同步、团队知识、个人信息 | 数据合规 | 数据合规 8 项（分类分级、PII、权限映射、留存、审计） |
| 在线召唤、RAG、引用溯源 | 工具类 | 冲突处理 + 回滚 |
| 远程代码执行、密钥、沙箱 | 安全红线（强信号，不可砍） | 供应链安全 + 最小权限 + 强制审计 |

**裁决序应用**：安全红线（远程 Skill 供应链）> 数据合规（跨系统权限映射）> 企业服务主线 > 各附属清单（全带）。

**产品本质判断**：这不是"AI 工具集合"，而是**以 Agent 为一等公民的团队协作操作系统**（AI-native Team Work OS）。核心差异点是把 Agent 从"对话助手"提升为"可分配任务、可担责、可审计的团队成员"。所有设计围绕此展开。

## 3. 能力域详细需求

### M1. Skill 可视化编辑（对应 R-01）

| 编号 | 功能需求 | 业务规则 | 验收标准（Given/When/Then） |
|---|---|---|---|
| FR-101 | 图形化创建 Skill | 字段：名称、唯一标识、描述、输入输出 Schema、权限声明、依赖 | Given 新建 Skill，When 保存，Then 生成标准 Skill 清单且可通过校验 |
| FR-102 | 提示词/脚本可视化编辑 | 支持提示词模板、脚本片段；脚本进入沙箱执行 | Given 编辑脚本，When 保存，Then 静态检查（禁止网络/文件越权）通过 |
| FR-103 | 在线调试台 | 支持单步执行、变量预览、输入样例集 | Given 输入样例，When 点击调试，Then 返回执行日志与最终输出 |
| FR-104 | 版本与发布 | 版本号语义化；草稿/已发布/已下线三态；下游引用关系可视化 | Given 下线被引用版本，Then 阻断并提示影响范围 |
| FR-105 | 变更审计 | 每次变更记录人、时间、diff | Given 任意历史版本，Then 可查看 diff 并回滚 |

**权限声明（关键）**：每个 Skill 必须显式声明所需能力（读文件/写文件/网络域名/调用 API/读知识库），发布时校验，越权声明直接阻断。

### M3. 工作流可视化编排（对应 R-03）

| 编号 | 节点类型 | 说明 |
|---|---|---|

### M4. Skills Hub 远程直读（对应 R-04）

| 编号 | 功能需求 | 业务规则 |
|---|---|---|
| FR-401 | 仓库注册 | 支持 Git 仓库 / HTTP 索引服务 / 内部制品库；支持认证（Token/OAuth/免密内网） |
| FR-402 | 远程直读（免下载） | 平台以远程引用方式加载 Skill：使用前按需拉取清单，内容不进本地工作区；执行在服务端沙箱完成 |
| FR-403 | 索引与检索 | 远端只同步元数据（名称/描述/版本/标签/权限声明），构建检索索引；内容按需拉取并缓存（可配置缓存 TTL） |
| FR-404 | 供应链安全（强信号，不可砍） | ① 来源白名单与签名校验；② 静态安全扫描（脚本危险 API）；③ 权限最小化强制；④ 三级信任等级（官方/组织内/社区）；⑤ 社区 Skill 强制沙箱+人工审核；⑥ 全量审计日志；⑦ 一键熔断（远程 Skill 可全平台下线） |
| FR-405 | 版本锁定 | 任务/工作流绑定 Skill 版本；上游变更不自动影响存量（避免静默行为漂移） |
| FR-406 | 离线降级 | 远程不可用时：可用本地缓存（声明版本）/ 明确阻断 / 人工介入，三种策略可配 |

> **风险提示**：免下载 ≠ 免执行。远程 Skill 仍是任意代码执行，必须以沙箱为唯一执行路径，禁止在用户主机或主进程内运行。

### M6. 知识管理：Confluence 同级（对应 R-06/07）

| 编号 | 功能需求 | 业务规则 |
|---|---|---|
| FR-601 | 多源接入 | Confluence（Cloud/DC）、Notion；按空间/数据库/页面粒度授权 |
| FR-602 | 双向同步 | 支持单向（导入/镜像）与双向；冲突策略：平台优先/远端优先/最新优先/人工裁决；同步周期与手动同步 |
| FR-603 | 权限映射（合规必带） | 远端页面权限 → 平台 ACL；平台不放大权限（不因同步获得越权访问）；权限变更在 SLA 内生效（如 15 分钟内） |
| FR-604 | 在线编辑 | 富文本 + Markdown 双模；块级编辑；附件/图片/代码块；页面树/标签/全文检索 |
| FR-605 | AI 润色 | 选中级/段落级/全文级；动作：润色、扩写、缩写、纠错、翻译、改写风格（正式/简洁/ persuasive→需替换为"客观"）、生成摘要与要点 |
| FR-606 | 版本与回滚 | 每次编辑版本化；支持差异对比与回滚；AI 改动标记为可一键还原 |
| FR-607 | 站内引用 | 平台页面可引用外部 Confluence/Notion 页面（只读引用卡片） |
| FR-608 | 审计 | 同步日志、编辑人、AI 改动标记、导出记录 |

**AI 润色关键约束**：润色必须可一键还原（保留原文 diff）、不得改变事实性数据与数字、支持术语词库保护（团队黑名单/白名单）。

## 4. 核心实体关系

```
Workspace(工作空间)
 ├── Member(成员) ── Agent(AI 成员，一等公民，有权限/身份/配额)
 ├── Task(任务) ── 状态机 ── Artifact(交付物) ── Comment/评审
 │     └── 执行轨迹：Workflow Run / Agent Run / Skill Call / Model Call
 ├── Skill ── 版本 ── 来源(Hub远程 / 本地自建) ── 权限声明 ── 安全评级
 ├── Agent定义 ── 版本 ── 组成(Skills/工具/模型/知识库/权限域)
 ├── Workflow ── 版本 ── Node/DAG
 ├── Knowledge ── 文档(块) ── 索引 ── 同步源(Confluence/Notion/本地)
 │     └── ACL ── 检索期过滤
 ├── Workflow/App ── API Key ── 限流/配额 ── 计量账单
 └── AuditLog(全局不可篡改) ── TraceID 串联以上全部实体
```

## 5. 关键状态机

**任务状态机**（单向流转，防重放）
```
待分派 ──分配──▶ 已分派 ──认领/开始──▶ 执行中 ──提交交付──▶ 待验收
   ▲                 │                     │                  │
   │                 └───释放/转人工───────┘            通过 │ 驳回
   │                                                       ▼   ▼
   └────────────────────── 已取消                      已完成 ◀┘（驳回回执行中）
                                                  已挂起（人工介入）
```

**工作流运行状态**：待运行 → 运行中 → 成功 / 失败（可重试）/ 已取消；人工节点 → 挂起待审批（超时策略生效）

## 6. 权限矩阵（节选）

| 角色 | 任务 | 知识 | Skill/Agent | 工作流 | API | 审计 | 计量 |
|---|---|---|---|---|---|---|---|
| 平台管理员 | 全部 | 全部 | 发布/下线 | 全部 | 签发 | 全部 | 全部 |
| 空间管理员 | 空间内 | 空间内 | 提交/发布到空间 | 空间内 | 空间内 | 空间内 | 空间内 |
| 团队成员 | 参与任务 | 授权空间 | 使用（不可发布） | 使用 | 自建 Key | 自身 | 自身 |
| Agent | 被授权任务范围 | 被授权知识域 | 只读自身 | 被触发 | 禁止 | 自身行为 | 自身配额 |
| 外部访客 | 无 | 指定页面只读 | 无 | 无 | 无 | 无 | 无 |

**铁律**：Agent 权限不得超过其创建者/所属成员的权限（权限继承上限），所有 Agent 行为以"该 Agent 主体 + 发起人"双重留痕。

## 10. 澄清问题清单（一次性确认）

1. **部署形态**：私有化部署 / SaaS / 混合？团队规模与并发量级？（决定容量与沙箱架构）
2. **业务模式**：完全开源免费，还是开源 + 企业版收费？收费点（席位/用量/私有化）直接决定 M7 计量设计的深度。
3. **Agent 执行环境**：是否已有可信代码执行沙箱（K8s/Firecracker/gVisor）？还是本项目需自研？
4. **Skills Hub 形态**：你自建的 Hub 是"仅自用"还是"对外开放 + 审核 + 分发"？后者需要建设审核与签名体系（工作量显著增加）。
5. **知识同步方向**：Confluence/Notion 是单向镜像还是真双向？后者冲突处理成本高。
6. **任务与 Jira 的关系**：本平台任务是自建工单体系，还是需要与 Jira/Teambition 双向同步？
7. **模型策略**：主要用哪家/哪些模型？是否需要自托管开源模型（涉 GPU 资源规划）？
8. **Agent 交付形态**：只交文本/文件，还是要能提 PR 到代码仓库、走 Code Review？
9. **合规边界**：知识库涉及的内容是否含个人信息/客户敏感数据？留存与脱敏要求？
10. **开源协议**：期望的开源协议（影响 Hub 与 SDK 生态设计）？
