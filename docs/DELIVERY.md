## 一、这是什么

**以 AI 成员为一等公民的团队协作工作台**。人类成员与 AI 成员在同一任务队列、同一套权限、同一份知识、同一套审计下协作。

核心设计：AI 不是「聊天助手」，而是**可被指派任务、可担责、可审计的团队成员** —— 它有独立身份、权限、配额，任务可指派给它，交付物需人类验收。

## 五、三条核心链路（端到端实测通过 19/19）

1. **任务闭环**：建任务 → 指派 AI → 自动执行（检索→沙箱→模型→交付）→ 落「审核中」→ 人工验收 → 「已完成」+ 收件箱通知解除
2. **技能沙箱执行**：已审核技能调用成功（`localFiles: 0`）；**未审核社区技能被拦 403/1012**；**含 `subprocess` 的脚本被拦 403/1010**（`details.reason=FORBIDDEN_API`）
3. **知识问答**：提问 → 按 ACL 过滤后检索 → 答案带溯源引用 → 反馈写入

## 七、关键决策（含取舍理由）

### 1. 数据库驱动选 `node:sqlite` 而非 `better-sqlite3`
`better-sqlite3` 需从 GitHub 下载 arm64 预编译二进制，本机连通性未验证；失败则要走 node-gyp 本地编译。内置驱动零下载零编译。已封装在 `db/client.ts`，`DB_DRIVER` 环境变量可切换。

### 2. actor 走请求级上下文（AsyncLocalStorage）而非逐层透传
审计需要「执行主体 + 发起人」双主体。最初 21 处调用点漏写 actor（模式统一为 `actorId: xxx ?? null`）。逐处修要动 60+ 编辑，且新增路径仍会漏。改为与 TraceID 同机制：`onRequest` 登记，`audit.write()` 自动兜底，**三者都没有则抛 1018**。

### 3. `null` 只表示「数据缺失」，不表示「没有发起人」
系统自动行为（如模型降级）的 `actor_id` 显式写 `SYSTEM_ACTOR_ID = 'system'`。否则界面无法区分「系统自动」与「数据丢了」。此语义已写入 `packages/shared/src/constants.ts` 与 README §7.1。

### 3.1 `initiator` 与 `actor` 同样需要兜底
`actor` 有了 ALS 兜底后，`initiatorId` 仍可能为空 —— 因为早先只兜底了 actor。
于是 `kb_space_created` / `skill_version_created` / `task_deleted` 等动作长期只有「执行主体」没有「发起人」，
而**技能页「保存声明」按钮就会触发 `skill_version_created`，演示时肉眼可见**。

修法：`initiatorId` 未显式提供时默认等于 `actorId`（绝大多数动作是「人自己操作」，发起人即执行主体）；
AI 代替人执行的路径（skill/task 的 AI 链路）都显式传两个值，不会被兜底覆盖；系统动作保持 `null`。

> **这个缺陷的发现方式值得记下**：它由**数据驱动**的检查发现（查库看哪条缺 initiator），
> 而纯代码扫描没发现 —— 因为扫描条件只查「无 actorId」与「actorId ?? null」，
> 漏掉了「有 actorId 但缺 initiatorId」这一形态。**两种方法各有盲区，都要用。**

### 4. 收件箱通知「解除」而非「标记已读」
`inbox()` 返回全部通知（含已读、排序靠后），只置 `read=1` 条目仍会挂在收件箱 —— 这正是「已验证任务还显示待验收」的根因。改为直接解除；历史可追溯性由 `audit_log` 保证。

### 5. 验收与流转路径副作用一致
`accept` 与 `transition {to:'done'}` **都会**解除收件箱通知。此前只有 `accept` 会，导致同一业务状态变化走不同接口产生不同结果（此缺陷由 README 如实记录现状时暴露）。

### 6. 草稿技能允许人工执行，AI 路径限已发布（DEF-04 的裁决）
技能库「调试台」需要执行未发布草稿，这是**正当需求**；AI 自动执行限 `published` 是**不同语义**（AI 不应跑未验证的技能）。两者不矛盾，故不改。

## 八、已知限制（如实列出，未粉饰）

### ⚠️ 最重要：角色权限矩阵未接入
`PermissionService.assertAction`（角色级权限矩阵）**从未被任何端点调用**（仅单测覆盖）。

也就是说：「人类与 AI 共享同一套权限」这个设计目前**只落地了数据域交集部分**（AI 有效权限 = min(自身声明, 创建者权限)），**角色级授权（管理员/空间管理员/成员）尚未接线**。

### 其他限制

| 项 | 说明 |
|---|---|
| 无鉴权 | `x-actor-id` 是纯客户端头，任何调用方可冒用**已存在**的成员身份（演示模式设计）。已加存在性校验（拒绝不存在的主体），但未做身份认证 |
| AI 执行全为 Mock | 5 个 `REPLACE_POINT`：`AiExecutor` / `Sandbox` / `ModelGateway` / `Retriever` / `HubClient`。真实模型、沙箱、向量检索、Hub 拉取均需替换实现 |
| 静态检查是子串黑名单 | 挡不住字符串拼接、编码混淆、动态 getattr。定位是「低成本第一道闸门」，真正兜底必须是沙箱运行时隔离（已在规则表上方标注局限） |
| 工作流编排未实现 | 不在本期四大模块范围（PRD 的 FR-WF） |
| 未验证项 | 真实沙箱执行、登录/角色授权、`/v1` stream/异步回调、限流压测、性能基准 |
