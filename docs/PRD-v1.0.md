## 一、背景与目标

### 1.1 背景

AI 编程助手（Codex、WorkBuddy、Multica 等开源项目）已把「人写代码」推进到「人指挥 Agent 干活」。但企业落地上仍存在结构性缺口：

| 现状问题 | 具体表现 |
|---|---|
| **能力孤岛** | Agent 只在命令行里，无法融入团队已有的任务、文档、协作流程 |
| **资产不可沉淀** | 团队调好的 Skill 只能存本地，新人无法复用，人员流动即资产流失 |
| **知识不入 Agent** | Confluence/Notion 里的规范、决策、历史无法作为 Agent 的可信上下文 |
| **执行不可控** | Agent 缺权限体系与审计，涉生产变更时无法放行 |
| **成本不可见** | Token 花费无法归因到项目/人/Agent，规模化后成本失控 |

当前市面产品各有其重：Agent 工具不擅长协作；协作工具（Jira、Confluence）不擅长 Agent；RAG 工具（Dify、RAGFlow）不擅长任务闭环。**没有一个平台让「人」和「Agent」在同一队列、同一条知识、同一套审计下工作。**

### 1.2 产品定位

> **以 Agent 为一等公民的团队协作操作系统。**
> 人类成员与 AI 成员在同一任务队列中协作，共享同一套权限、知识、审计与计量体系。

三条铁律（贯穿全文，作为设计不可突破的底线）：

1. **Agent 权限不得超过其创建者/所属成员的权限**（权限继承上限）
2. **远程 Skill 一律沙箱执行，禁止在用户主机或主进程内运行**（免下载 ≠ 免执行）
3. **所有 Agent 行为以「Agent 主体 + 发起人」双重留痕**，审计不可篡改

### 1.3 成功指标与口径

| 编号 | 指标 | 口径定义 | 首版目标值 | 统计周期 |
|---|---|---|---|---|
| M-01 | Agent 任务渗透率 | 平台新建任务中由 Agent 承接的比例 = Agent 承接任务数 ÷ 平台新建任务总数 | ≥ 30% | 周 |
| M-02 | 任务时长压缩比 | (人工基线均时长 − Agent 承接任务均时长) ÷ 人工基线均时长 | ≥ 40% | 月，基线取项目上线前 3 个月 |
| M-03 | Agent 一次通过率 | Agent 提交交付后未经驳回即验收通过的比例 | ≥ 70% | 周 |
| M-04 | 单任务成本可控率 | 有明确成本上限且未触发熔断的任务占比 | 100% | 日 |
| M-05 | 高危安全事件 | Skill 越权执行、数据越权访问、密钥泄露事件数 | 0 | 日（实时告警） |
| M-06 | Agent 执行成功率 | Agent 执行未因平台内部错误（5xx）失败的比例 | ≥ 95% | 日 |
| M-07 | 知识检索命中率 | RAG 问答中被用户采纳（未点踩且未重问）的比例 | ≥ 65% | 周 |

## 二、名词与术语

| 术语 | 定义 |
|---|---|
| Workspace（工作空间） | 团队级最高隔离单元，含成员、任务、知识库、Skill、Agent |
| Agent（AI 成员） | 具备独立身份、权限、配额、可被分配任务的一等协作主体 |
| Skill（技能） | 可复用的原子能力单元，含输入输出 Schema、提示词、脚本、权限声明 |
| Skill Hub | Skill 的注册与分发中心，支持自建远程仓库 |
| Workflow（工作流） | 由节点组成的有向图，用于编排任务执行过程 |
| 节点（Node） | 工作流最小单元，含触发器、LLM、Skill、Agent、条件、人工、代码、并行、迭代 |
| Artifacts（产物） | 执行产生并被追踪的输出物：代码、文档、报表、图表 |
| 知识库（Knowledge） | 文档集合经解析切块建索引后的可检索资产 |
| 知识空间（Space） | 知识的组织单元，与 Confluence Space / Notion 页面树对应 |
| 溯源引用（Citation） | RAG 答案中指向来源页面/块/版本的链接 |
| TraceID | 贯穿一次任务执行全链路的追踪 ID |
| 幂等键 | 保证重复请求不产生重复副作用的唯一标识 |
| 权限声明 | Skill/Agent 对所需能力（文件/网络/API/知识库）的显式声明 |

## 三、需求范围

### 3.1 本期包含（v0.1 ~ v0.3，MVP + 两个迭代）

- 统一身份与权限（人 + Agent 双主体，RBAC + 数据权限）
- 代码执行沙箱与密钥托管
- Skill 可视化编辑、调试、版本发布
- Skills Hub 远程仓库直读（免下载 + 供应链安全）
- Agent 可视化编排、版本发布、灰度
- 工作流可视化编排引擎（条件分支、人工节点、并行、迭代）
- 任务协作：人机同队列、状态机、留痕、验收、SLA、看板
- 通知与待办聚合
- Artifacts 产物管理
- 多模型网关与降级
- 全链路可观测与审计
- 计量配额与预算熔断
- 知识管理：Confluence/Notion 单向镜像同步、在线编辑、AI 润色

### 3.2 本期不包含（明确不做）

| 不做项 | 原因 | 计划版本 |
|---|---|---|
| 双向同步冲突自动裁决 | 成本高，先做单向镜像 + 人工裁决 | v0.5 |
| Jira/Teambition 双向同步 | MVP 先自建任务体系 | v0.6 |
| Agent 自主提 PR 并合入主分支 | 风险高，v0.3 仅允许提 PR 且必须人工 Review | v0.1（提 PR）/ 合入（不做） |
| 计费与真实扣款 | 开源版仅出用量报表，不做支付 | v0.5（企业版） |
| 多语言界面 | 首发中文，i18n 资源预留 | v0.5 |
| 移动端原生 App | 移动端访问走响应式 Web | v0.4 |
| Agent 递归自主编排超过 3 层 | 成本与失控风险 | v0.6 评估 |

## 四、方案对比与选型说明

### 4.1 整体技术路线对比

| 维度 | 方案 A：单体 + 内置沙箱 | 方案 B：微服务 + 独立执行面（推荐） | 方案 C：完全 Serverless |
|---|---|---|---|
| 实现成本 | 中 | 高 | 中 |
| 沙箱安全 | 弱（同进程风险） | 强（独立执行面隔离） | 中（厂商沙箱，定制受限） |
| 扩展性 | 弱 | 强（执行面独立扩容） | 中 |
| 私有化适配 | 好 | 好 | 差（依赖云厂商） |
| 自研可控性 | 高 | 高 | 低 |
| 结论 | 不选：安全与扩展不达标 | **推荐** | 不选：私有化场景不适配 |

**选定方案 B**：控制面（Web/API/编排/权限/审计）+ 执行面（沙箱运行）分离部署，执行面可独立扩缩容与网络隔离。

### 4.2 Skill 执行模式对比

| 维度 | A：本地执行 | B：服务端沙箱（推荐） | C：端侧执行 |
|---|---|---|---|
| 主机安全 | 风险高 | 低 | 低 |
| 权限管控 | 难 | 易（文件系统+网络白名单） | 中 |
| 密钥安全 | 易泄露 | 临时注入不落盘 | 中 |
| 启动延迟 | 低 | 中 | 低 |
| 适配 Hub 免下载 | 不适配 | **适配** | 不适配 |
| 结论 | 不选 | **推荐** | 备选（未来离线场景） |

### 4.3 演进路径

```
v0.1 单闭环  →  v0.2 编排引擎  →  v0.3 知识管理  →  v0.4 知识库 RAG
                                                          ↓
              v0.6 评测回归 / 多 Agent 协作  ←  v0.5 开放 API + 计费
```

**触发条件**：v0.1 上线后 M-06 执行成功率 ≥ 95% 且 M-03 一次通过率 ≥ 60%，方可启动 v0.2。

## 五、用户角色与使用场景

### 5.1 角色定义

| 角色 | 画像 | 核心诉求 |
|---|---|---|
| 团队成员（执行者） | 一线研发/运营/职能，熟练使用 IM，AI 使用经验浅 | 不学新工具也能把活派给 AI；看得懂 AI 在干什么 |
| Agent 负责人 | 团队 lead，负责提效 | 把重复工作标准化为 Skill；看 Agent 的产出质量与成本 |
| 平台管理员 | 运维/技术负责人 | 权限可控、密钥不泄露、审计可查、成本可归因 |
| 知识 Owner | 文档与规范的维护者 | 文档能被 Agent 正确引用；规范更新能立刻生效 |
| 外部贡献者（开源） | 社区 Skill 作者 | 发布 Skill 到 Hub、有安全审核与信誉机制 |

### 5.2 核心场景

**S-1 我把一件重复的事交给 AI**
成员在任务创建时选择 Agent 作为负责人 → Agent 认领 → 执行（调用 Skill）→ 提交交付物与执行说明 → 成员审阅并验收通过 / 打回并说明理由。

**S-2 我把团队的重复工作沉淀成 Skill**
Agent 负责人在可视化编辑器中录制一次执行过程 → 配置输入输出与权限声明 → 调试通过 → 发布到团队空间 → 其他成员在分配任务时可选该 Skill 匹配的 Agent。

**S-3 引入团队已有的 Skills 生态**
管理员注册自建 Hub 仓库 → 平台只同步 Skill 元数据做检索 → 用户使用某 Skill 时按需拉取并沙箱执行，本地工作区不落盘。

**S-4 AI 需要遵守我们的规范**
成员问「这个接口怎么用」→ 侧边栏召唤 → 平台在 Confluence 已同步的知识空间内检索 → 回答附引用链接 → 点击可跳转原页面。

**S-5 外部系统调用我们的 Agent**
开发者用 API Key 触发工作流 → 异步回调拿结果 → 在用量报表看到这次调用归因到哪个项目与调用方。

### 5.3 角色-流程泳道

| 阶段 | 成员 | 平台 | Agent | 知识源 |
|---|---|---|---|---|
| 建任务 | 建任务、选负责人、写验收标准 | 校验权限与配额 | — | — |
| 执行 | 旁观 / 答疑 | 派发、留痕、计量 | 认领、调用 Skill、产出 | 按需检索 |
| 验收 | 审阅交付物、通过/打回 | 记录结果、更新指标 | 接收反馈上下文 | — |
| 沉淀 | — | 更新 Skill/知识 | — | 归档有效做法 |

## 六、功能需求

> 编号规则：`FR-<模块>-<序号>`。模块码：SK(Skill) / AG(Agent) / WF(Workflow) / HB(Hub) / TK(Task) / KM(知识管理) / KB(知识库) / API / GOV(治理)

### 6.1 SK — Skill 生命周期（M1）

| 编号 | 需求 | 业务规则 | 验收标准（Given/When/Then） |
|---|---|---|---|
| FR-SK-01 | 图形化创建 Skill | 必填：名称、唯一标识（团队内唯一）、描述、输入 Schema、输出 Schema、权限声明；选填：标签、示例集、图标 | Given 新建 Skill 表单，When 填写必填项并保存，Then 系统生成标准 Skill 清单且通过结构校验 |
| FR-SK-02 | 权限声明填写与校验 | 声明项：读文件/写文件/网络域名/调用外部 API/读知识库/读任务数据；发布时校验，声明与实际行为不符时运行期拦截 | Given Skill 声明「仅读文件」，When 运行期尝试发起网络请求，Then 请求被沙箱阻断并记录审计 |
| FR-SK-03 | 提示词与脚本编辑 | 提示词支持变量占位符；脚本仅支持白名单语言（Python/Node.js）；脚本保存前静态检查 | Given 编辑脚本引入未授权网络库，When 保存，Then 静态检查失败并指出具体行 |
| FR-SK-04 | 在线调试台 | 支持单步执行、变量预览、样例集回归、输出对比 | Given 选定样例集，When 点击调试，Then 返回每步日志、耗时、Token 与最终输出 |
| FR-SK-05 | 版本管理 | 版本号语义化（Major.Minor.Patch）；状态：草稿/已发布/已下线 | Given 创建 Major 版本，When 发布，Then 下游引用方可显式迁移 |
| FR-SK-06 | 依赖与影响面分析 | 展示被哪些 Agent/工作流引用 | Given 下线被引用版本，Then 阻断操作并列出全部引用方 |
| FR-SK-07 | 版本回滚 | 可回滚至任意历史版本，回滚产生新版本记录 | Given 回滚至 v1.2，Then 生成新版本并记录回滚原因与操作人 |
| FR-SK-08 | 变更审计 | 记录人、时间、diff | Given 查看任意历史版本，Then 可对比并回滚 |

### 6.2 AG — Agent 编排（M2）

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-AG-01 | 可视化编排 | 配置项：名称、系统角色定义、模型与参数、可用 Skill 集合、可调用工具/MCP、知识库挂载、数据域权限 | Given 通过表单配置 Agent，When 保存，Then 生成 Agent 定义并可在调试台试运行 |
| FR-AG-02 | 能力边界声明 | 必须声明可访问的项目/知识空间/任务队列；越界调用运行时拦截 | Given Agent 未授权空间 Z，When 请求访问，Then 拒绝并记录 |
| FR-AG-03 | 上下文预算 | 可视化配置来源优先级：系统指令 > 任务描述 > 知识检索 > 历史；可设 Token 上限与超限降级（截断/摘要） | Given 上下文超上限，Then 按配置降级且在执行轨迹中标注 |
| FR-AG-04 | 权限继承上限 | Agent 有效权限 = min(自身声明, 创建者权限)，运行时强制 | Given 创建者仅空间 A 权限，Then Agent 声明全空间也仅在 A 内生效 |
| FR-AG-05 | Agent 间委派 | 支持派发子任务给其他 Agent；委派深度上限 3 层；总预算上限 | Given 委派深度达 3，When 继续委派，Then 拒绝并提示 |
| FR-AG-06 | Agent 版本化与灰度 | 版本绑定；支持按任务比例灰度 | Given 灰度 20%，Then 20% 新任务走新版本，可按比例回退 |

### 6.3 WF — 工作流编排（M3）

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-WF-01 | 节点库 | 9 类节点：触发器、LLM、Skill、Agent、条件、人工、代码、并行、迭代 | Given 打开编辑器，Then 可拖拽全部 9 类节点至画布 |
| FR-WF-02 | 触发器 | 支持：定时、Webhook、任务创建、知识库更新、人工 | Given 配置 Webhook 触发，Then 收到请求后校验签名并启动运行 |
| FR-WF-03 | 条件分支 | 多路 + 默认 + 兜底异常分支 | Given 条件未命中任何分支，Then 走兜底分支 |
| FR-WF-04 | 人工节点 | 支持审批/补充信息/确认；超时策略：自动通过/驳回/挂起 | Given 超时策略为挂起，Then 任务挂起并通知负责人 |
| FR-WF-05 | 并行与迭代 | 并行分支需设聚合策略（全成功/任一成功）；迭代需设最大次数 | Given 迭代 10 次未收敛，Then 终止并告警 |
| FR-WF-06 | 代码节点 | 沙箱执行，白名单语言，资源限额 | Given 代码节点执行超时，Then 强制终止并记录 |
| FR-WF-07 | 节点级重试与幂等 | 所有有副作用节点自动注入幂等键；可配重试次数与间隔 | Given 节点超时后重试，Then 副作用不重复 |
| FR-WF-08 | 运行限额 | 单次运行 Token 上限、费用上限、时长上限，超限熔断 | Given 达费用上限，Then 停止运行并通知发起人 |
| FR-WF-09 | 运行可观测 | 节点级耗时/Token/输入输出快照；支持回放 | Given 查看一次运行，Then 可逐节点查看快照并从任意节点重跑 |
| FR-WF-10 | 敏感变量加密 | 密钥类变量加密存储，运行时解密注入，日志脱敏 | Given 查看运行日志，Then 敏感值显示为 `***` |

### 6.4 HB — Skills Hub 远程直读（M4）

| 编号 | 需求 | 业务规则 | 验收标准 |
|---|---|---|---|
| FR-HB-01 | 仓库注册 | 支持 Git / HTTP 索引服务 / 内部制品库；支持 Token、OAuth、免密内网 | Given 注册 Git 仓库，When 同步，Then 拉取 Skill 元数据并建索引 |
| FR-HB-02 | 远程直读（免下载） | 平台以远程引用方式加载；本地工作区不落盘；执行在服务端沙箱 | Given 使用远程 Skill，When 执行结束，Then 检查本地工作区无该 Skill 文件 |
| FR-HB-03 | 元数据索引 + 按需拉取 | 仅同步名称/描述/版本/标签/权限声明；内容使用时按需拉取，缓存 TTL 可配 | Given 未使用某 Skill，Then 平台仅持有其元数据 |
| FR-HB-04 | 版本锁定 | 任务/工作流绑定具体版本；上游变更不自动影响存量 | Given 上游发布新版本，Then 存量任务行为不变 |

## 八、业务流程与状态流转

### 8.1 核心主流程：人机协作任务闭环

```
成员建任务 → 选负责人（人或 Agent）→ [Agent 侧]
  → 认领 → 生成执行计划 → 调知识库检索 → 调 Skill（沙箱）→ 产出交付物
  → [人侧] 审阅 → 通过（结束）/ 打回（附理由 → 回执行中）
```

### 8.2 任务状态机

```
待分派 ──分配──▶ 已分派 ──认领──▶ 执行中 ──提交──▶ 待验收
   │                  │              │                 │
   │                  └──释放/转人工──┘            通过 │ 驳回
   │                                                    ▼   ▼
   └────────────────── 已取消                      已完成 ◀┘（回执行中）
                                        已挂起（人工介入 / SLA 超时）
```

**规则**：
- 单向流转，禁止回退（驳回为「待验收→执行中」的前向跳转，非回退）
- 每次状态变更写入审计（操作人/时间/原因）
- 已验收任务的任何修改需新建任务，不允许修改已验收结果

### 8.3 工作流运行状态

```
待运行 → 运行中 ─┬─ 成功
                 ├─ 失败（可重试，受重试上限）
                 ├─ 已取消
                 └─ 挂起（人工节点等待，超时策略生效）
```

### 8.4 Skill 发布状态机

```
草稿 ──调试通过──▶ 待审核 ──审核通过──▶ 已发布 ──下线──▶ 已下线
  ▲                   │                     │              │
  └─────审核驳回───────┘                     └──回滚/新版本─┘
```

### 14.2 用户故事

**US-1**：作为团队成员，我希望在创建任务时把负责人选为 AI，这样重复工作可以自动完成，而不需要我额外学一套工具。
- Given 我在任务创建页选择「Agent」标签，Then 出现 Agent 成员列表并显示各自能力标签
- Given 我按标签筛选，Then 只显示匹配的 Agent
- Given Agent 完成任务并提交交付物，Then 我看到完整执行轨迹再决定验收

**US-2**：作为 Agent 负责人，我希望把我调好的流程发布成 Skill，这样团队每个人都能复用，而不用反复指导。
- Given 我在可视化编辑器配置输入输出与权限声明，When 调试通过并发布，Then 团队其他成员可在任务中选用
- Given 我下线被引用的版本，Then 系统阻断并告诉我哪些地方在用

**US-3**：作为知识 Owner，我希望平台同步 Confluence 后能在站内编辑，这样规范更新不需要在两个系统间来回切。
- Given 空间已同步，When 我在站内编辑页面，Then 保存后生成新版本且可回滚
- Given 我用 AI 润色一段文字，Then 可以对比原文并一键还原

**US-4**：作为平台管理员，我希望能一键下线某个有问题的 Skill，这样投毒事件能被快速止损。
- Given 我点击熔断，Then 全平台该 Skill 立即不可用，且存量运行中的任务被终止并告警

### 14.3 关键决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 执行模式 | 服务端沙箱 | 免下载≠免执行，主机安全不可妥协 |
| 架构 | 控制面/执行面分离 | 沙箱独立扩容与网络隔离 |
| 同步方向 | 本期单向镜像 | 双向冲突成本高，先验证核心闭环 |
| Hub 范围 | 首期组织内自用 | 社区审核体系人力需求大，后置 |
| 任务体系 | 自建（不依赖 Jira） | 保持开源项目零外部依赖 |
| Agent 合入 | 仅提 PR，不自动合入 | 变更风险控制，人工 Review 必过 |
